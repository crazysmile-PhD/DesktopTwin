# 诊断与修复的实际边界

本文替换旧的“自动修复可行性验证”。旧文把单机观察、设计建议和已实现行为混在一起，不能继续作为兼容性保证。当前入口是 `ChildSessionEnvironmentCheck` 和 `EnvironmentFixer`，界面在用户选择修复后调用。

## 检查与动作

| 检查 ID | 当前实现可能执行的修复 |
| --- | --- |
| `termservice-stopped` | 启动 TermService |
| `termservice-disabled` | 改回手动启动类型并启动服务 |
| `rdp-disabled` | 调整本机 RDP 开关，并按条件重启 TermService；策略值可能阻止修复 |
| `rdp-wrapper` | 尝试还原原生 ServiceDll 配置，处理识别到的残留并重启服务 |
| `hello-only` | 修改当前实现识别的 Hello 限制注册表值，按结果提示后续操作 |
| `termservice-dll-type` | 修正 ServiceDll 值/类型 |
| `termservice-key-broken` | 修正实现所列的服务键偏差 |
| `rdp-tool-persistence` | 对命中的计划任务/Run 自启项尝试备份并删除 |
| `rdp-security-downgraded` | 把实现判定过低的 RDP-Tcp 参数补回目标值 |
| `termsrv-dll-tampered` | 尝试备份恢复或 SFC 修复，并复核；可能转为独立扫描 |

此表描述代码会做什么，不证明每个判断都是故障根因，也不证明这些值是所有 Windows 版本的官方默认配置。账户密码、系统版本及域策略等不能由一次注册表写入普遍解决。

## 结果应怎样理解

“检测到”可能来自注册表值、文件、任务关键词或上次连接错误，不等于获得完整因果证据。没有权限、扫描不完整、SFC 未完成或超时，应保留未知，不应写成“环境已正常”。

重启服务前代码检查非控制台活动会话；检查与真正停止之间仍有竞态窗口。备份是尽力而为，个别动作在备份失败后仍可能继续，不能统一宣传成“所有修改都完整备份且一键可逆”。请以具体返回结果和日志为准。

修复与正常连接的职责不同。启动分身会启用系统 Child Sessions 功能；它不会为了正常连接自动执行表内全部修复。程序内的“阻塞项”是实现选择，不应自动提升为 Windows Child Session 的通用前置条件。

## 使用与复核

只处理与当前证据对应的条目。系统策略由组织管理时，保留其来源，不要依靠重复写本机值与之对抗。修复可能影响其他 RDP 工具；执行前保存工作并确认会话状态。

修复后重新采集实际值并尝试原始操作。注册表回读成功、扫描进程已启动、服务已运行、桌面已连接是四种不同结果；它们都不能单独证明目标问题已经消失。

进一步验证请记录 Windows 构建、原值、动作、返回结果、复核值及实际行为。仓库没有维护覆盖所有版本的自动修复矩阵，也不应引用旧文中某台机器的账户信息作为通用证据。

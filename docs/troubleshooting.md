# 排查手册

先记录可复现步骤、发生时间和程序版本/提交。程序缺陷、Windows 状态及第三方行为都可能造成问题，单凭一个提示不能确定责任。

## 启动之前

程序要求管理员权限。框架依赖包需要 .NET 10 Desktop Runtime；只有 SDK 或其他类型的运行时不等价于桌面运行时。发布包应保留其需要的同目录文件。

对于下载文件，先确认来源。发布方提供 SHA256 时可用 `Get-FileHash .\DesktopTwin.exe -Algorithm SHA256` 对照；哈希一致只说明与参考文件相同，不证明安全。签名、SmartScreen 声誉和安全软件检测是不同信息，不能承诺解除文件锁定后所有提示都会消失。

本仓库 `main` 上已修复的代码不一定已打包为 Release。复现时同时记录版本号和构建提交；必要时记录 exe 的 SHA256。

## 连接慢、黑屏或看似卡死

1. 记录卡在哪一步：双击至主窗口、连接必要预检、凭据、正在连接，还是注销。
2. 打开“控制中心 → 诊断”，复制环境信息和同一时间段日志。窗口关闭后不再发布在途诊断结果。
3. 检查日志里是否有连接失败及扩展错误。单次连接预算为 60 秒；设置重连回调缺失时也会按尝试预算结束，明确报超时。设置变更还可能有有界重连重试。等待长不自动等于死锁。

ActiveX 的 `Connected` 属性和 WTS 状态可能在切换中短暂不一致。程序现在会共用在途连接，并在启动入口核对会话状态；若仍黑屏，请附上前后完整时序，不要只截取最后一行“超时”。

重连由会话层统一控制，不再由控件额外排队或无限自动恢复。断开最多观察 60 秒，等待会话退出活动状态最多 10 秒，登录最多等待 60 秒；首次连接错误退避 4 秒重试一次，设置重连错误退避 2/4/8 秒重试三次。超时停止本轮操作；待应用设置留给下次手动启动。连续设置会合并，失败时不要将保存成功当成已重新登录成功。已经登录后意外断开会提示失败，可核对日志后重新启动。

同步报告的参数或权限异常直接显示失败，修改配置后再启动。游戏鼠标接收端启动失败会及时显示原始原因并关闭等待中的握手，不再用通道取消提示替代启动错误。状态由连接/断线回调和窗口操作刷新，环境设置可在诊断中手动重检。

窗口关闭/托盘退出现在只等 Windows 接受注销请求，再关闭主程序。Windows 仍可能继续结束会话，因此立即重新打开不一定立刻可连。关闭系统 Child Sessions 功能等需要确认完成的操作，仍异步观察最多 15 秒。不要把再次点击“启动”当成中止注销。退出/注销会结束分身里的程序。

连接必要预检不再扫描计划任务、启动项或触发系统文件校验；这些检查仍在诊断面板。日志中的“性能计时”可区分主窗口初始化、App 创建至首帧、必要预检、RDP 登录结果、Windows 注销请求下发及退出资源清理。首帧计时不覆盖 UAC、运行时加载与单文件解包，不能直接当作双击至窗口的总时间。

若应用完全无响应，记录进程 PID、是否还能操作托盘，以及其他 Windows 程序是否正常。能取得挂起转储时可提供给维护者；转储可能包含内存中的私人内容，不要直接公开上传。

## 凭据提示或自动登录失败

微软描述的常规子会话流程会自动使用父会话身份，并列有例外；“每次都必须输密码”不是可靠的通用前提。[Child Sessions](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions)

实际出现密码框时，核对当前账户类型及提示中的用户名。`C:\Users` 下的目录名可能与登录名不同；Windows Hello PIN 也不等同于账户密码。[Windows Hello FAQ](https://learn.microsoft.com/en-us/windows/security/identity-protection/hello-for-business/hello-faq)

程序的“保存并验证密码”可检查所选账户凭据，自动登录密码以 DPAPI 当前用户作用域保存。应用内保存凭据与 Windows 开机自动登录是两件事；不要为了排查分身，默认去关闭系统登录保护或更改账户类型。

等待凭据期间启用自动登录会立即开始监听；关闭或清除密码立即取消监听，不必重连。已经进入的系统调用仍需返回，后续填写和提交会检查取消及开关状态；自动重试期间仍交给用户输入。

诊断中的密码/Hello 提示包含运行时推断与注册表检查。它们不证明云端密码过期，也不能证明某账户绝无可用认证方式。失败后避免连续提交同一密码，先核对错误与账户策略。

## 家庭版、策略或第三方 RDP 修改

程序对 Windows 家庭版会提示但不直接阻止；仓库没有覆盖全部系统版本的兼容矩阵。“微软 Child Session 文档排除了家庭版”以及“多数家庭版一定可用”都不是本项目可据此保证的结论。

诊断会检查 TermService、部分 RDP/账户策略、ServiceDll、可疑任务和系统文件。这是当前实现的判定，不是 Windows 官方先决条件的完整清单。检查可能因权限、缓存或工具状态返回未知。先看具体证据，再决定是否修复，不要批量调整注册表或关闭认证。

打开或激活面板只读取系统文件的已有验证证据；需要新的完整性结果时点击现有“重新检测”。没有做过校验或缓存已过期会保留未知，不代表文件已正常。系统修复后的显式复核不变。

连续重检会取消旧校验的排队等待，旧任务取得执行权后也必须复核是否仍有效。已运行的 SFC 继续按原有预算收尾，结果过期时丢弃；重新点击不会中止正在执行的系统扫描。

确实安装过修改 RDP 的工具时，先保留其来源和变更记录。恢复原生服务配置会影响该工具；详见 [修复范围](auto-repair-feasibility.md)。

## 升级后仍有旧版热键代理

本版本已移除全部 UU 集成。打开主窗口后会在后台清理旧的 `DesktopTwinSessionAgent` 自启项及 `%AppData%\DesktopTwin\DesktopTwin.Agent.exe`，不修改 UU 软件或服务。若日志显示清理失败，确认旧文件没有被其他程序占用后重新启动 DesktopTwin。旧日志保留用于排查。

## 游戏帧率与资源占用

按 [性能排查](performance.md) 做相同场景对比。分身不是免费的第二块屏幕：它包含额外会话和游戏进程。日志里的图形属性接受值不是 FPS 或实际硬解证据。

程序不会绕过游戏的多开、权限或反作弊限制；具体兼容性需要针对目标程序验证。

## 鼠标转视角

“控制中心 → 相对鼠标（实验性）”默认关闭，开关直接启停游戏鼠标，不重连 RDP。当前实现为本机 Raw Input 捕获与分身会话内的接收端，不依赖原生 RDP 相对模式成功协商。

- 出现“游戏鼠标已启用”表示接收端身份、协议和进程创建均已确认。它不代表游戏已接受输入。启动失败时普通 RDP 操作继续，查看日志中的“会话内游戏鼠标不可用”，关闭再开启该选项可重试。
- 游戏隐藏光标时自动捕获；按住 Alt 可操作菜单，Ctrl+Alt 可主动释放，再点击画面恢复。窗口失焦、隐藏或观看模式也会释放。画面内仍显示光标时，保持普通桌面操作。
- 前台未捕获时由一个计时器按 250ms 间隔被动发现光标状态，回复供下次检查使用；本地输入窗口暂时缺失时不查询远端，恢复后仍遵守发现间隔；已捕获时使用 32ms 检查和活动租约。被动查询不会授权输入，后台停止发现。间隔不代表真实游戏的输入延迟。
- 本地测试 API 的 `sessionInput` 区分 `ready`（通道）、`captured`（本机捕获）、`rawMoves`（硬件原始移动次数）和 `status.injectedMoves`（会话内成功插入的移动次数）。接收端回报自己的会话与光标状态；旧的原生 RDP 属性回读不再作为这条通道的成功证据。
- `rawMoves` 增加而 `injectedMoves` 不增加时检查队列、租约与连接错误；二者增加但游戏视角不动时，继续检查游戏输入兼容性。`SendInput` 成功不保证所有 Raw Input 游戏均接收。
- 分别测试左右/上下转动、持续转向、Alt 菜单、Escape、Alt+Tab、窗口缩放、观看模式、断线与退出。不得仅靠限制游标范围宣布转视角已修复。
- 若操作异常，取消该选项后对比普通输入，无须等待重连。反馈时附上开关状态、Windows 构建号、`mstscax.dll` 版本、游戏名称和对应日志。

## 分屏时画面比例

默认的“适应窗口（推荐）”按窗口实际空间调整远端分辨率，适合一半游戏、一半影片等分屏用途。选择固定游戏分辨率后，画面按远端实际比例等比居中，空余区域显示黑边。“保持宽高比”开关已移除，旧版关闭状态也会被忽略。

内容太小时先选“控制中心 → 桌面分辨率 → 适应窗口（推荐）”，或选择较低的固定分辨率。若提示自动分辨率未接受或未确认，当前连接仍会保留；再次调整窗口可重试，拒绝或两秒未确认不会永久屏蔽相同尺寸的后续请求。持续失败时可保存工作后手动重新连接。固定分辨率下，自适应缩放显示完整桌面，关闭时采用 1:1 像素，较小窗口可能需要滚动。

窗口标题栏跑到屏幕外的问题由启动恢复、拖动与工作区检查共同处理。首次升级会取消旧小窗启动状态；普通窗口和小窗都会按当前工作区限制大小，保存的位置不会再使用不可拖动的标题栏坐标。反馈时附上程序提交、窗口模式、分辨率、显示器布局/DPI 和前后截图。

调整窗口或在固定/自动分辨率之间切换后出现灰色区域、旧偏移或裁切时，检查是否使用包含 `RdpControlContainer` 修复的构建。新布局由容器保持原生控件填充，并在远端尺寸变更后刷新缩放；只改变背景颜色不能验证裁切已解决。请在相同游戏场景中复测窗口大小和比例往返，并检查四边界面是否完整。

## 提交反馈

请在 [本仓库 Issues](https://github.com/crazysmile-PhD/DesktopTwin/issues) 提供操作步骤、时间、Windows 构建号、版本/提交、环境快照，以及 `%AppData%\DesktopTwin\logs\` 对应片段。用户名、路径等私人信息可以先打码。

开发测试也会写日志；测试故意制造的异常不能计作实际使用故障。请用启动时间和复现步骤把记录对应起来。历史发行说明只描述当时版本，当前行为以源码和本手册为准。

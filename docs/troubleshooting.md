# 排查手册

先记录可复现步骤、发生时间和程序版本/提交。程序缺陷、Windows 状态及第三方行为都可能造成问题，单凭一个提示不能确定责任。

## 启动之前

程序要求管理员权限。框架依赖包需要 .NET 10 Desktop Runtime；只有 SDK 或其他类型的运行时不等价于桌面运行时。发布包应保留其需要的同目录文件。

对于下载文件，先确认来源。发布方提供 SHA256 时可用 `Get-FileHash .\DesktopTwin.exe -Algorithm SHA256` 对照；哈希一致只说明与参考文件相同，不证明安全。签名、SmartScreen 声誉和安全软件检测是不同信息，不能承诺解除文件锁定后所有提示都会消失。

本仓库 `main` 上已修复的代码不一定已打包为 Release。复现时同时记录版本号和构建提交；必要时记录 exe 的 SHA256。

## 连接慢、黑屏或看似卡死

1. 记录卡在哪一步：启动前诊断、凭据、正在连接、UU 目标确认，还是注销。
2. 打开“控制中心 → 诊断”，复制环境信息和同一时间段日志。窗口关闭后不再发布在途诊断结果。
3. 暂时关闭 UU 视角锁定，重复同一条手动操作，判断自动纠正是否参与。
4. 检查日志里是否有连接失败及扩展错误。单次连接预算为 60 秒；设置重连回调缺失时也会按尝试预算结束，明确报超时。设置变更还可能有有界重连重试。等待长不自动等于死锁。

ActiveX 的 `Connected` 属性和 WTS 状态可能在切换中短暂不一致。程序现在会共用在途连接，并在确保连接时核对会话状态；若仍黑屏，请附上前后完整时序，不要只截取最后一行“超时”。

注销已改为异步观察，最多等待 15 秒；出现未完成提示后，Windows 可能仍在结束会话。不要把再次点击“启动”当成中止注销。退出/注销会结束分身里的程序。

若应用完全无响应，记录进程 PID、是否还能操作托盘，以及其他 Windows 程序是否正常。能取得挂起转储时可提供给维护者；转储可能包含内存中的私人内容，不要直接公开上传。

## 凭据提示或自动登录失败

微软描述的常规子会话流程会自动使用父会话身份，并列有例外；“每次都必须输密码”不是可靠的通用前提。[Child Sessions](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions)

实际出现密码框时，核对当前账户类型及提示中的用户名。`C:\Users` 下的目录名可能与登录名不同；Windows Hello PIN 也不等同于账户密码。[Windows Hello FAQ](https://learn.microsoft.com/en-us/windows/security/identity-protection/hello-for-business/hello-faq)

程序的“保存并验证密码”可检查所选账户凭据，自动登录密码以 DPAPI 当前用户作用域保存。应用内保存凭据与 Windows 开机自动登录是两件事；不要为了排查分身，默认去关闭系统登录保护或更改账户类型。

诊断中的密码/Hello 提示包含运行时推断与注册表检查。它们不证明云端密码过期，也不能证明某账户绝无可用认证方式。失败后避免连续提交同一密码，先核对错误与账户策略。

## 家庭版、策略或第三方 RDP 修改

程序对 Windows 家庭版会提示但不直接阻止；仓库没有覆盖全部系统版本的兼容矩阵。“微软 Child Session 文档排除了家庭版”以及“多数家庭版一定可用”都不是本项目可据此保证的结论。

诊断会检查 TermService、部分 RDP/账户策略、ServiceDll、可疑任务和系统文件。这是当前实现的判定，不是 Windows 官方先决条件的完整清单。检查可能因权限、缓存或工具状态返回未知。先看具体证据，再决定是否修复，不要批量调整注册表或关闭认证。

确实安装过修改 RDP 的工具时，先保留其来源和变更记录。恢复原生服务配置会影响该工具；详见 [修复范围](auto-repair-feasibility.md)。

## UU 切换失败、离线或反复切换

- 手动操作会暂停自动锁定。切到主机后，分身保持断开，里面的程序继续运行。
- 15 秒内未观测到目标串流端，就报告失败；程序不再无限重启服务。
- “当前没有串流端”只说明暂时无法确认 UU 落点，请连接后核对。
- 锁定连续三次纠正后仍不稳定会自动关闭。先验证手动切换，再重新开启。
- 服务确实异常时，可主动执行“修复 UU 串流”。停止已经下发后，即使会话操作被取消，也会用有界预算尽力启动服务回来。

反馈时说明 UU 版本、切换前后的目标、串流端会话号，以及是否开着锁定。不要把“结束串流端成功”当作“UU 已切到目标”的证据。

## 游戏帧率与资源占用

按 [性能排查](performance.md) 做相同场景对比。分身不是免费的第二块屏幕：它包含额外会话和游戏进程。日志里的图形属性接受值不是 FPS 或实际硬解证据。

程序不会绕过游戏的多开、权限或反作弊限制；具体兼容性需要针对目标程序验证。

## 鼠标转视角

“控制中心 → 相对鼠标（实验性）”默认关闭。需要测试游戏转视角时可开启，程序会重连；没有连接时保存到下次连接。需要支持该能力的 Windows 11 24H2 或更新系统及 RDP 控件/服务器，不为旧系统提供独立代理转发。

- 登录后提示“已请求”只表示两项鼠标属性写入被接受，尚不能证明游戏收到相对位移。提示未完整接受时查看同一时间的日志，程序会尽力复位两项并继续连接；复位失败同样记录，不能当作已恢复的证据。
- 日志中的“相对鼠标”记录请求与属性接受情况；“RDP 鼠标输入模式回调”记录控件报告的模式。没有回调不单独证明失败，有回调也不证明某个游戏兼容。
- 在目标游戏中分别测试左右与上下转动、持续转向、返回菜单、Alt+Tab、窗口/全屏切换，以及观看模式的键鼠屏蔽。界面选择仍表示请求的设置，实际模式可能由系统和目标程序改变。
- 若操作异常，取消该选项并等待重连完成，再对比普通输入。反馈时附上开关状态、Windows 构建号、`mstscax.dll` 版本、游戏名称和对应日志。

## 提交反馈

请在 [本仓库 Issues](https://github.com/crazysmile-PhD/DesktopTwin/issues) 提供操作步骤、时间、Windows 构建号、版本/提交、环境快照，以及 `%AppData%\DesktopTwin\logs\` 对应片段。用户名、路径等私人信息可以先打码。

开发测试也会写日志；测试故意制造的异常不能计作实际使用故障。请用启动时间和复现步骤把记录对应起来。历史发行说明只描述当时版本，当前行为以源码和本手册为准。
